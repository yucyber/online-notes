# Bug 解决流程规范

排查本项目 bug 时的标准流程，按顺序执行。

## 1. 复现与定位（先查后猜）

1. 复现问题，确认现象和触发条件。
2. **先检索 `docs/debug-records.md`**，看是否已有同类问题的根因记录，避免重复踩坑。
3. 定位相关代码文件，用日志、断点、数据库查询等方式**确认根因**，而不是凭猜测。
4. 涉及数据存储的，先确认数据库里字段的**实际存储类型与内容**（如 ObjectId vs 字符串）。

## 2. 修复

1. 基于确认的根因做最小化、针对性修改。
2. 修改后检查 lint（`read_lints`），确认无新引入错误。
3. 需要用户重启服务或手动验证时，明确告知操作步骤。

## 3. 验证（证据先行）

1. 让用户或自己执行验证步骤，确认现象消失。
2. 不要只凭"看起来好了"下结论，要有可观测的证据（接口返回、日志、数据库记录）。

## 4. 记录（确认成功后）

**当用户明确确认 bug 已解决时**，将解决方案追加进 `docs/debug-records.md`，格式见 `debug-record-format.md`。

- 记录内容：现象、根因、修复方案、相关文件、经验教训。
- 记录时机：用户说"好了/解决了/成功了"之类确认后。
- 未确认解决前不要写入，避免记录错误结论。
