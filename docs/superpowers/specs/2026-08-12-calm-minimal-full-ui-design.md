# 全项目 Calm Minimal UI 整改设计

## 目标

以 `docs/ui-mockups/editor-calm-minimal-20260810.html` 为唯一视觉基准，将 Calm Minimal 风格扩展到在线笔记项目的全部前端页面。整改只调整页面结构、视觉层级和必要的交互反馈，不改变现有 API、权限语义和核心业务流程。

## 视觉基准

- 背景使用灰白层次：页面背景、白色内容面板和浅灰辅助区域形成层级。
- 主强调色沿用雾蓝，深石墨用于主要按钮；不引入墨绿、大面积渐变或高饱和装饰色。
- 卡片使用轻边框、低阴影和 10–16px 圆角，避免悬浮感过强。
- 字体、间距和信息密度接近现有编辑器 HTML；标题清晰，但不使用夸张字号。
- 图标统一使用项目已有 `lucide-react`，不混用 Emoji 或其他图标体系。
- 状态色只用于成功、警告、错误和权限提示，不承担页面装饰。

## 全局页面框架

登录后的页面共享同一套应用外壳：左侧导航、页面标题区和主内容区。左侧导航沿用设计稿的浅色侧栏、雾蓝选中态和紧凑图标，补充仪表盘、笔记、分类、标签、知识库、看板、思维导图、通知、活动和设置入口。窄屏下侧栏折叠为图标栏或抽屉，不压缩主要内容。

页面标题区提供标题、简短说明和最多两个主要操作。搜索、筛选和批量操作放在标题区下方的工具行，避免每个页面自建不同的操作布局。

## 通用组件

- `PageHeader`：统一标题、说明、面包屑和页面操作。
- `Panel` / `Card`：统一边框、圆角、内边距和背景。
- `Button` / `IconButton`：区分主要、次要、危险和纯图标操作。
- `Input` / `Select` / `SearchField`：统一高度、边框、focus 状态和错误说明。
- `Badge` / `StatusChip`：用于分类、标签、权限和运行状态。
- `EmptyState` / `LoadingState` / `ErrorState`：统一空数据、加载和失败反馈。
- `Dialog` / `Dropdown` / `Toast`：统一浮层外观；错误进入全局 Toast，页面内只保留与内容直接相关的状态。
- 表格、分页和列表行使用一致的 hover、选中与键盘 focus 样式。

优先复用现有组件并调整样式；只有多个页面确实重复时才抽取新组件，避免为视觉整改建立过重的组件体系。

## 页面设计

### 登录与注册

使用居中的单列认证卡片，保留轻量品牌标识和必要说明。背景延续设计稿的灰白径向层次，表单保持紧凑，不增加宣传轮播或复杂插画。

### 仪表盘

顶部展示少量关键数据，主体使用“最近笔记”“快捷入口”“近期活动”三个区域。统计卡片保持低对比度，不使用大面积彩色图表。快捷入口只覆盖创建笔记、进入知识库和搜索等高频操作。

### 笔记列表

使用统一页面标题和搜索筛选工具行。列表卡片突出标题、摘要、更新时间、分类与标签；次要操作收进菜单。视图切换、分页和空状态保持轻量。分类和标签筛选必须清楚可撤销。

### 分类与标签

分类使用紧凑列表或双栏卡片，展示名称、笔记数量和必要操作；标签使用可扫描的列表或标签矩阵，同时提供搜索。创建和编辑使用小型 Dialog，不建设复杂管理工作台。

### 知识库与知识图谱

知识库列表沿用笔记卡片语言，详情页使用标题区、关联笔记区和图谱区。知识图谱画布保留更大的可用面积，配置和操作收进浅色侧面板，状态反馈采用 Toast 或紧凑状态条。

### 看板与思维导图

两者共享页面外壳，但主体保持各自画布特征。顶部只保留返回、标题、保存状态和必要操作，属性配置放入可折叠侧面板，避免多层工具栏抢占空间。

### AI 功能

突出输入、上下文范围、运行状态和结果。AI 入口使用深石墨按钮或雾蓝选中态，不使用发光、强渐变和大面积紫色。历史记录、失败重试和结果操作采用普通列表与按钮语义。

### 通知、活动与设置

通知和活动使用时间顺序列表，通过图标、标题和轻量状态点区分类型。设置按账户、编辑偏好、协作和 AI 配置分组，使用窄表单布局；危险操作独立放在页面底部。

### 编辑器

编辑器继续执行已确认的专项设计：统一 Tiptap 编辑体验、自动保存状态、可折叠左右面板、紧凑工具栏、只读权限收口和全局 Toast。视觉上直接贴近现有 HTML，不重新设计。

## 响应式与可访问性

- 桌面端保留完整侧栏；中等宽度折叠文字；移动端使用抽屉导航。
- 主操作在窄屏下保持可见，次要操作进入菜单，避免横向滚动工具栏遮挡内容。
- 所有可交互控件提供可见 focus、明确 label 和足够点击区域。
- 颜色不是状态的唯一表达方式；警告和错误同时提供图标或文字。
- 尊重 `prefers-reduced-motion`，折叠和浮层动画保持短促且可关闭。

## 实施边界

- 不修改后端接口、数据模型、ACL 或协作鉴权。
- 不在本轮增加新业务功能，也不重写知识图谱、看板或思维导图引擎。
- 不要求每个页面单独制作高保真 HTML；使用统一设计令牌和组件规则直接落地。
- 现有功能若缺少入口，只补充导航或呈现；无法确认的业务语义不自行发明。

## 验证策略

整改按全局外壳、核心内容页、扩展页面、编辑器和最终收口分批实施。每批只运行受影响的定向测试、`type-check` 或必要 lint；不在每个小改动后执行全量测试。全部页面完成后统一运行前端测试、lint、type-check、production build，并进行一次桌面端与移动端浏览器验收。

## 验收标准

1. 登录后页面使用一致的侧栏、标题区、颜色、圆角、间距和状态组件。
2. 仪表盘、笔记、分类、标签、知识库、AI、通知、活动、设置、看板和思维导图均与编辑器 HTML 保持同一视觉语言。
3. 分类、标签及页面主要操作易发现，次要操作不过度占据页面空间。
4. 现有业务流程、权限限制和 API 调用保持不变。
5. 桌面端和移动端无关键操作被遮挡或不可达。
6. 全局只保留一套 Toast、按钮、表单和基础卡片样式。
7. 最终前端质量门禁和浏览器核心流程验收通过。
