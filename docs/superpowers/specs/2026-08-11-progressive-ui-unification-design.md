# 在线笔记渐进式 UI 统一设计

**日期：** 2026-08-11  
**状态：** 已确认，2026-08-12 扩展全项目整改范围
**范围选择：** 方案 B——以已完成的编辑器整改为基线，先统一设计基础与全局壳层，再分批迁移全部业务页面
**代码基线：** `f24e714 fix(editor): 修复等待保存时断网重试`

## 1. 背景

当前产品同时存在四套视觉来源：`globals.css` 的全局变量、Tailwind 配色、基础组件内联样式，以及编辑器专用 `editor-tokens.css`。旧 Dashboard 壳层与新版编辑器局部样式叠加后，出现导航、卡片、按钮、间距、圆角和状态提示互不一致的问题。

上一轮编辑器改造还保留了 `ws[on] sync[ok]`、常驻“保存/重连”等开发诊断 UI，并遗漏右侧属性栏。最终审查同时发现自动保存乱序覆盖和 API 快照覆盖离线 Yjs 内容两条数据安全风险。新一轮不能只处理视觉表面，必须先确保内容不会因 UI 改造链路丢失。

## 2. 目标

1. 建立一个全站唯一的设计 token 和基础组件来源。
2. 统一所有 Dashboard 页面共享的侧栏、顶部栏、背景和内容容器。
3. 完整落地已确认的 Calm Minimal 编辑器，而不是把新版编辑器嵌入旧壳层。
4. 统一笔记列表、新建笔记、查看/编辑笔记这一条主要用户链路。
5. 让未迁移页面立即继承统一壳层和基础组件，再按业务域分批完成全项目视觉整改。
6. 先消除自动保存、离线恢复和只读权限中的静默数据损坏风险。
7. 分类、标签、知识库、AI、通知、活动、设置、看板和思维导图使用与编辑器一致的 Calm Minimal 视觉语言。

## 3. 非目标

- 本轮不重做仪表盘、知识库、分类、标签、通知、设置、活动日志、白板和思维导图的业务信息架构；只统一页面结构、视觉层级和必要的交互反馈。
- 本轮不引入新的大型 UI 组件库，不迁移到另一套 CSS 框架。
- 本轮不增加装饰性动画、渐变背景、玻璃拟态或大面积品牌色。
- 本轮不修改后端业务接口，除非自动保存并发保护经验证必须增加版本条件；该项需要单独设计与审批。
- 本轮不以静态 HTML 设计稿替代真实 React 页面验收。

## 4. 视觉方向

采用内容优先的 Calm Minimal 风格：浅色背景、蓝灰中性色、少量克制蓝色作为交互强调。界面应像稳定的生产力工具，不呈现墨绿主题、紫色渐变或常见“AI 面板”视觉。

### 4.1 色彩

- 页面背景：冷灰白，不使用渐变。
- 面板/纸张：白色或接近白色。
- 主文字：深蓝灰；次要文字：中灰；弱提示：浅灰。
- 主交互色：克制蓝色，仅用于选中、焦点、主要动作和链接。
- 成功、警告、错误使用语义色，不替代品牌色。
- 正文、按钮、表单和 Toast 的文字对比度至少满足 WCAG AA。

### 4.2 字体与密度

- 中文优先使用系统中文无衬线字体栈，避免为了“设计感”加载不完整的远程中文字体。
- 正文基准字号 16px，辅助文字不得低于 12px。
- 页面密度保持中等：导航紧凑，正文留白充分。
- 编辑器正文以阅读舒适为优先，工具栏允许局部横向滚动，但页面本身不得横向溢出。

### 4.3 形状、阴影与图标

- 使用 6/8/12px 三档圆角；同类组件必须采用同一档。
- 阴影只区分浮层和普通面板，卡片 hover 不做大幅上浮或缩放。
- 图标统一使用 `lucide-react`，不使用 emoji 或手绘 SVG。
- 图标按钮必须有 `aria-label` 和 Tooltip；移动端可点击区域至少 44×44px。

### 4.4 动效

- 仅保留 150–200ms 的状态过渡。
- 不使用滚动入场动画和装饰性编排。
- `prefers-reduced-motion` 下关闭非必要动画和过渡。

## 5. 信息架构与页面壳层

### 5.1 全局壳层

所有 `/dashboard/*` 页面共享同一个 `AppShell`：

- 左侧主导航：可完全收起，桌面端记忆用户显式选择；窄屏为 overlay。
- 顶部栏：仅保留导航折叠、面包屑、搜索入口、通知、主题和账户入口。
- API 延迟、连接诊断和“触发同步”不作为常驻客户 UI。
- 主内容区不再统一套用厚重白色大卡片；页面自行选择 `PageSurface` 或无边框内容区。
- AI 助手入口位置统一，不与 Toast、滚动条和页面主操作重叠。

### 5.2 编辑器页面

桌面端由三个明确区域构成：

- 左侧：全局导航，由 `AppShell` 管理。
- 中间：标题、轻量保存状态、编辑工具栏和纸张正文。
- 右侧：目录、协作者、属性，可独立收起。

编辑器规则：

- 不展示 `ws[...]`、`sync[...]`、原始延迟等开发诊断。
- 不展示常驻“保存”“重连”“触发同步”按钮。
- 自动保存状态用轻量文本；失败与重试使用统一右上角 Toast。
- 评论和协作使用 Lucide 图标按钮与 Tooltip。
- Markdown 与富文本保持统一编辑体验。
- 标题、可见性、分类、标签与正文进入同一可靠保存模型。

### 5.3 笔记主链路

笔记列表、新建页和编辑页共享：

- 相同的页面标题、操作区、筛选控件、空状态和分页样式。
- 相同的按钮、输入框、卡片、Badge、Dialog 和 Toast。
- 明确的 loading、empty、error、read-only 状态，不把内部错误对象直接显示给用户。

### 5.4 其余页面

第一阶段先让全部页面继承新壳层、token 和基础组件默认样式，并修复明显溢出或不可读问题。随后按业务域分批迁移，避免单个提交横跨全部页面：

- 仪表盘：使用少量关键数据、最近笔记、快捷入口和近期活动，不堆叠大色块或装饰性图表。
- 分类：使用紧凑列表或双栏卡片，突出名称、笔记数量和必要操作；创建和编辑使用小型 Dialog。
- 标签：使用可搜索的标签列表或矩阵，明确笔记数量和筛选状态，不让彩色标签破坏全局色彩层级。
- 知识库：列表沿用笔记卡片语言；详情页由关联笔记和图谱区域组成，图谱配置收进浅色侧面板。
- AI：突出输入、上下文、运行状态和结果；使用深石墨或雾蓝强调，不使用发光、强渐变和大面积紫色。
- 通知与活动：使用可扫描的时间顺序列表，通过图标、标题和轻量状态点区分类型。
- 设置：按账户、编辑偏好、协作和 AI 配置分组，采用窄表单布局；危险操作独立放在页面底部。
- 看板与思维导图：保留各自画布，顶部只放返回、标题、保存状态和必要操作，属性进入可折叠侧面板。
- 登录与注册：使用居中单列认证卡片和轻量品牌标识，不增加宣传轮播或复杂插画。

这些页面只调整呈现，不修改现有 API、数据模型、ACL 或业务流程。无法从现有调用链确认的业务语义不自行补造。

## 6. 组件与样式架构

### 6.1 唯一 token 来源

新增全局产品 token 文件，负责颜色、字体、间距、圆角、阴影、层级、控件高度和动效。`globals.css` 只负责 reset、主题入口和全局可访问性规则；`editor-tokens.css` 只允许编辑器专属排版，不再重复定义品牌色或通用控件。

禁止在业务组件中新增未经说明的 raw hex、任意阴影和独立圆角。现有 Tailwind 色值逐步映射到语义 token。

### 6.2 基础组件

先统一以下组件，再迁移页面：

- `Button` / `IconButton`
- `Input` / `Textarea` / `Select`
- `Card` / `PageSurface`
- `Dialog` / `Drawer`
- `Badge` / `StatusText`
- `Tooltip`
- `Toast`

基础组件不得通过 React 本地 hover/focus state 拼接大量内联样式；交互样式由 class 和 token 管理，保证 SSR、键盘、暗色和 reduced-motion 一致。

## 7. 数据与权限安全前置门禁

在继续视觉迁移前必须完成：

1. 自动保存改为单请求串行、latest-wins 队列，禁止旧请求晚到覆盖新内容。
2. IndexedDB/Yjs 本地内容未完成恢复前，不得应用 API seed；非空本地文档不得仅凭时间戳被 API HTML 静默覆盖。
3. 只读用户在正文、标题、属性、评论、协作邀请和 programmatic command 上保持零写入。
4. 协作重连必须刷新过期 room ticket，鉴权终态不得被旧 provider 状态覆盖。
5. AI retry 必须保持单请求，避免双击并发覆盖消息。

## 8. 分阶段交付

### 阶段 0：数据安全纠偏

修复自动保存并发、离线 Yjs 恢复、ticket 刷新、AI retry，并用回归测试证明不会覆盖新内容。

### 阶段 1：设计基础与全局壳层

建立 token 和基础组件，替换 Dashboard 壳层，去除常驻调试状态。所有页面在此阶段获得一致的外框。

### 阶段 2：编辑器与笔记主链路

完整实现三栏编辑器、右侧属性、统一自动保存，以及笔记列表/新建页的一致样式。

### 阶段 3：验收与迁移清单

完成编辑器与笔记主链路的自动化门禁、真实浏览器视觉对照和数据安全场景；以 `f24e714` 的已验收成果作为后续迁移基线。

### 阶段 4：核心业务页面

迁移仪表盘、分类、标签、知识库和 AI 页面。每个业务域只运行受影响的聚焦测试、`type-check` 或必要 lint，不在每个小改动后执行全量测试。

### 阶段 5：扩展页面与最终收口

迁移通知、活动、设置、看板、思维导图和认证页面，完成桌面端与移动端兼容检查。全部页面完成后统一运行一次前端 Jest、lint、type-check、production build 和真实浏览器核心流程验收。

每个阶段独立提交、独立审查。阶段 0–3 已由 `f24e714` 基线覆盖；阶段 4–5 不改变编辑器既有安全边界，最终门禁通过前不得声称“全项目 UI 已完成”。

## 9. 验收标准

### 9.1 视觉一致性

- 1440、1024、768、375px 下页面无横向溢出。
- Dashboard 壳层、编辑器、笔记列表和新建页使用相同 token 与基础组件。
- 仪表盘、分类、标签、知识库、AI、通知、活动、设置、看板、思维导图和认证页面与编辑器保持同一视觉语言。
- 已确认设计稿中的编辑器结构在真实路由中成立，不出现新旧壳层叠加。
- 产品 UI 中不存在 `ws[`、`sync[`、API 延迟或常驻保存/重连按钮。

### 9.2 交互与可访问性

- 所有图标按钮有可访问名称和 Tooltip。
- 键盘可完成左右栏收起/恢复、主要导航、编辑器操作和 Toast 关闭。
- Toast 关闭后焦点回到触发元素或下一条可操作 Toast。
- 点击目标、对比度、focus-visible 和 reduced-motion 满足本规格要求。

### 9.3 数据安全

- 逆序完成的保存请求不能让服务器最终内容回退。
- 离线编辑后关闭、重开、恢复网络不会被旧 API 快照覆盖。
- metadata-only、title-only 和正文修改都可恢复并持久化。
- reader 浏览和打开抽屉不会产生任何写请求或 Yjs mutation。
- 过期 ticket 可获取新 ticket 并重新连接；鉴权失败不无限重试。

### 9.4 验证证据

- 实施过程中按业务域运行聚焦测试；最终统一执行的全量 Jest、lint、type-check 和 production build 全部退出 0。
- 浏览器验收必须记录真实 URL、viewport、操作、断言和脱敏截图。
- 未执行的双端协作、AI live 或移动真机验证必须标记 `UNVERIFIED`，不能写成通过。

## 10. 风险控制与停止条件

- 单个任务不得同时重构业务逻辑和大范围视觉样式。
- 若基础组件迁移导致三个以上业务页面出现不同类型回归，停止扩张并先修复组件契约。
- 各业务页面达到统一 token、壳层、组件和响应式要求后即停止，不追求逐像素复刻编辑器或静态 HTML。
- Critical/Important 审查问题必须清零；Minor 只记录，不无限优化。
