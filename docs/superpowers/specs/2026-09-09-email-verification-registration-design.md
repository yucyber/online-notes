# 邮箱验证码注册设计

## 背景与目标

当前注册接口只校验邮箱格式和唯一性，提交邮箱与密码后会立即创建账号并登录。项目需要接入 QQ 邮箱 SMTP，让新用户必须证明自己能够接收该邮箱的验证码，避免使用虚假邮箱注册。

本次只改造新用户注册流程。已有账号的登录、会话 Cookie、数据与权限不受影响。

## 用户流程

1. 用户在注册页填写邮箱。
2. 用户点击“获取验证码”，前端请求发送接口。
3. 后端校验邮箱、频率限制和账号状态，通过 QQ SMTP 发送 6 位数字验证码。
4. 用户填写验证码、密码和确认密码并提交注册。
5. 后端原子校验并消费验证码，随后创建用户、签发 JWT，并沿用现有安全 Cookie 登录。
6. 验证码错误、过期或已使用时不创建账号，前端展示可操作的中文提示。

登录页目前存在“账号不存在时自动注册”的路径。该路径会绕过邮箱验证，因此本次将其移除，账号不存在时改为引导用户进入注册页。

## API 与数据契约

### 发送验证码

新增 `POST /api/auth/email-code`：

```json
{
  "email": "user@example.com"
}
```

成功时返回通用成功消息。接口受 IP 级 NestJS throttle 保护，并在 Redis 中对规范化邮箱实施 60 秒发送冷却。已注册邮箱不发送验证码；响应不得暴露 SMTP 配置、授权码或验证码。

### 注册

现有 `POST /api/auth/register` 请求增加必填字段：

```json
{
  "email": "user@example.com",
  "password": "example-password",
  "verificationCode": "123456"
}
```

验证码校验通过后立即消费，只能使用一次。用户创建与现有 JWT/Cookie 返回行为保持不变。

## 后端设计

### 邮件发送

新增独立邮件服务，使用 `nodemailer` 连接 QQ SMTP。配置全部来自环境变量：

- `SMTP_HOST`
- `SMTP_PORT`
- `SMTP_SECURE`
- `SMTP_USER`
- `SMTP_PASSWORD`
- `MAIL_FROM`

启动时不主动发送测试邮件。首次发送时若配置缺失或 SMTP 失败，接口返回服务暂不可用，并记录不含凭据和验证码的错误信息。

### 验证码安全

- 使用密码学安全随机数生成 6 位数字验证码。
- Redis 只保存验证码的 HMAC 摘要，不保存明文；摘要密钥复用服务器端 `JWT_SECRET` 作为本项目当前部署的秘密材料。
- 验证码有效期 10 分钟。
- 同一邮箱 60 秒内不可重复发送；新验证码会覆盖旧验证码。
- 同一验证码最多允许失败 5 次，超过后立即失效。
- 校验、失败次数更新和成功消费通过 Redis 原子操作完成，避免并发请求重复使用同一验证码。
- 邮箱在所有步骤统一执行 trim 与小写规范化。

### 失败语义

- 参数格式错误：`400 Bad Request`。
- 验证码错误、过期、已使用或尝试次数耗尽：统一返回 `400`，不区分内部状态。
- 发送过于频繁：`429 Too Many Requests`。
- SMTP 未配置或临时失败：`503 Service Unavailable`。
- 邮箱已注册：保持现有注册冲突语义；发送阶段不发送邮件，并使用通用提示减少账号枚举信息。

## 前端设计

注册页增加验证码输入框与“获取验证码”按钮：

- 邮箱格式合法时才能获取验证码。
- 发送成功后显示 60 秒倒计时并禁用重复发送。
- 注册按钮提交邮箱、验证码、密码和确认密码。
- 邮件发送失败、验证码无效及注册冲突均使用现有 toast/表单错误样式展示。
- 不把 SMTP 参数、授权码或任何邮件发送逻辑放入浏览器端。

登录页只执行登录。遇到不存在的账号时展示“账号不存在，请先注册”，并提供注册页入口，不再隐式创建账号。

## 配置与部署

示例配置加入仓库的 `.env.production.example`，真实值只写入 ECS 的 `/opt/online-notes/.env.production`。该文件权限继续保持 `600`，不得提交 Git。

Docker Compose 将 SMTP 变量注入 backend 容器。修改部署包后，仅需重建 backend、frontend 和 nginx；Redis 数据卷继续保留。

## 测试与验收

后端测试覆盖：

- 发送成功、冷却限制及 SMTP 失败。
- Redis 中不保存验证码明文。
- 正确验证码可注册且只能使用一次。
- 错误验证码累计尝试次数，达到上限后失效。
- 过期或缺少验证码无法注册。
- 邮箱规范化后一致匹配。
- 已有登录与安全 Cookie 行为不回归。

前端测试覆盖验证码字段、发送按钮状态、倒计时、注册请求参数，以及登录页不再自动注册。

上线验收：用一个未注册的真实邮箱获取验证码并完成注册；随后重复验证码注册必须失败，原有账号仍可正常登录。日志与响应中不得出现 SMTP 授权码或验证码。

## 不在本次范围

- 找回密码和修改邮箱。
- 邮件营销、通知邮件及 HTML 品牌模板系统。
- 自建邮件服务器或域名邮箱。
- 对历史账号补做邮箱验证。
