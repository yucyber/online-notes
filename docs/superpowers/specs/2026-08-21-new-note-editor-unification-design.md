# 新建笔记页对齐详情页设计

## 背景与目标

当前新建页只借用了部分 editor 样式，没有复用详情页的左侧目录、页面网格、顶部栏和右侧大纲，又增加了“仅本地”提示、独立属性弹窗及可见性选择，因此仍像另一套产品。

本次让新建页与详情页复用同一套左侧导航、header、toolbar、paper 和大纲。创建态只保留临时标题与正文、笔记属性、创建按钮和失败反馈。未保存笔记继续本地编辑，不请求 room ticket，不建立 WebSocket 或 IndexedDB 协作房间。

## 方案

抽取并复用详情页的展示单元与 CSS 结构，创建态保留独立数据流。`EditorWorkspaceSidebar` 直接用于两页；header 通过明确的创建态接口复用；大纲复用同一组件和 heading 提取逻辑。

这比复制详情页 JSX 更不容易再次漂移，也避免进入页面就产生空白草稿。不会把创建态塞进包含 ACL、自动保存、评论和版本逻辑的完整 `NoteEditorShell`。

## 页面结构

### 左侧导航

- 使用 `editor-layout-grid` 和 `EditorWorkspaceSidebar`。
- 展示品牌、返回、搜索和已有笔记目录；新建项不伪造 note id。
- 点击已有笔记先执行未保存确认，再跳转详情页。
- 沿用详情页的折叠状态与宽度偏好。

### 顶部与编辑区

- 面包屑显示“我的笔记 > 未命名笔记/当前标题”。
- 右侧只显示“笔记属性”和“创建笔记”；删除“仅本地”、评论、协作和自动保存状态。
- toolbar、paper、滚动和响应式规则沿用详情页类名。
- 标题输入位于 paper 内，正文使用 `<TiptapEditor localOnly />`。
- 创建态屏蔽评论及依赖真实 note id 的资源命令。
- 右侧大纲与详情页使用相同 DOM、样式和折叠偏好，并随正文标题更新。

### 笔记属性与可见性

- 使用详情页的 `NoteEditorMetadataPanel` 与 `EditorNoteProperties`。
- 面板仅含分类和标签，不显示可见性，也不显示尚不存在的历史版本。
- 新建请求固定提交 `visibility: 'private'`。
- 创建后 owner 可在协作/分享入口修改可见性；`public` 表示系统内所有已登录账号可读。

## 数据与权限边界

1. 页面加载目录、分类和标签；元数据失败不阻断编辑。
2. 创建前标题、正文和属性只保存在本地状态。
3. 空标题不发送请求；创建失败保留输入并显示错误。
4. 创建成功跳转 `/dashboard/notes/{id}`，再启用评论、协作、分享、版本和远程资源。
5. 创建前没有真实 id，不调用 ACL、评论、版本、协作和笔记资源接口。

## 测试与验收

- 断言新建页具有详情页网格、左侧导航、header、toolbar、paper 和大纲。
- 断言不存在“仅本地”、评论、协作、历史版本和可见性控件。
- 断言分类/标签通过详情页属性组件呈现。
- 断言创建固定提交 `visibility: 'private'` 且保存去重有效。
- 保持本地模式不请求 room ticket 且可写的回归测试。
- 运行相关 Jest、type-check、lint、`git diff --check`。
- 同视口浏览器截图对照两页，并确认 Network 无 `/room-ticket` 400、控制台无应用错误。

## 非目标

- 不修改后端权限或创建接口。
- 不在创建前启用评论、协作、公开分享、版本或远程资源。
- 不引入新依赖，不重构无关业务逻辑。
