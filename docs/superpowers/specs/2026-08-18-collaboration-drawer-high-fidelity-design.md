# 协作侧栏高保真改造设计

## 背景与目标

当前协作抽屉由通用卡片、按钮和列表拼装，信息层级、密度、交互入口和视觉语言都与设计稿差异较大。此次改造以 `.superpowers/brainstorm/codex-20260818110807/content/collab-drawer-directions.html` 为唯一视觉基线，重构编辑器内的协作抽屉，并接入设计稿呈现的成员与邀请操作。

“完全对齐”指抽屉结构、尺寸、间距、色彩、边框、圆角、字体层级、按钮形态、菜单位置、hover/focus/disabled 状态和窄屏行为均以设计稿中的 CSS 数值为准，不用项目通用卡片或按钮的默认样式近似替代。设计稿中的演示壳、说明标题和主题切换控件不属于产品界面，不移植到项目。

## 范围

### 本次实现

- 重构右侧协作抽屉的标题栏、滚动区和三个内容分组。
- 展示笔记可见性、现有成员和待接受邀请。
- 支持修改普通成员角色、移除成员、发送邀请、重新发送邀请和撤销邀请。
- 发送成功后使用项目 toast 反馈，不在设计稿之外增加常驻成功卡片或操作区。
- 为 ACL 响应补充安全的成员展示字段，使成员行可以显示名称、邮箱和头像，而不是裸露 ObjectId。
- 复用实时协作参与者信息标记当前在线成员；无法确认在线状态时不伪造在线状态。
- 支持 `readOnly` 展示模式、加载状态、空状态、操作中状态和失败反馈。
- 桌面端使用右侧固定抽屉，窄屏使用全宽抽屉。

### 本次不实现

- 不改变 ACL 或邀请的数据模型。
- 不引入新的成员搜索服务、组织通讯录或邮件投递系统。
- 不改造评论抽屉。
- 按用户要求，本轮 UI 实现后暂不运行测试；测试与视觉回归在 UI 确认后补充。

## 视觉规格

抽屉桌面端宽度严格为 340px，高度占满编辑器视口，并在窄屏下降为视口宽度。抽屉使用专属语义 token 一一映射设计稿中的 `surface`、`surface-muted`、`surface-hover`、`line`、`line-strong`、`text`、`text-secondary`、`muted`、`accent`、`focus`、`danger`、`black` 和 `white`；明暗主题的值均以设计稿为准。字体栈沿用设计稿的系统字体栈。桌面端只有左侧 1px 分隔线，抽屉本体不增加设计稿中不存在的圆角或阴影。页面遮罩只承担现有弹层关闭语义，不改变抽屉本体的视觉参数。

标题栏高度 56px，左右 padding 分别为 16px 和 14px。左侧为 20px Users 图标与“协作”标题，间距 10px，标题为 14px/700；右侧关闭按钮为 32px 正方形、8px 圆角。内容区 padding 为 14px，分组间距 16px，相邻分组增加 16px 顶部 padding 和 1px 分隔线。分区标题下边距 10px，使用 11px/700 muted 文本、`.08em` 字距和 uppercase 视觉规则。

可见性行采用浅灰底、8px 圆角、`10px 12px` padding 和 10px 内容间距；锁形图标为 20px accent 色，主文案为 13px/640。私有笔记显示“仅受邀成员可见”，组织或公开可见性映射为语义准确的文案。

成员行使用 `32px 1fr auto` 三列网格、10px 列间距、至少 48px 高、`6px 2px` padding 和 8px 圆角，hover 时切换为 `surface-muted`。名称为 13px/620 单行省略文本，补充信息为 12px muted 文本并有 2px 顶部间距。头像严格为 32px 圆形、1px 边框和 12px/700 文字；本人/所有者使用深色头像。在线点为右下角 10px 圆点、2px surface 描边：实时 awareness 中存在为 `#36b37e`，不在当前 awareness 中为 `line-strong` 灰点。

角色控件最小宽度 72px、高度 30px、左右 padding `10px 9px`、5px 内容间距和 999px 圆角，使用 12px/650 文本。所有者行次要文案显示“所有者”，行尾弱化胶囊显示“可编辑”且不可操作；普通成员显示“只读”或“可编辑”并带下拉指示；待接受邀请显示“待接受”黄色胶囊并带下拉指示。浅色和暗色待接受状态分别使用设计稿中的黄色 token。

邀请表单严格使用 `minmax(0, 1fr) auto auto` 三列网格和 10px 间距。输入框高 36px、左右 padding 11px、8px 圆角，内部搜索图标与输入文字间距 8px；focus 状态使用 accent 边框和设计稿的 2px focus halo。权限选择器高 36px、左右 padding 10px、8px 圆角和 18px 下拉图标；它是与视觉稿一致的自定义菜单触发器，不使用浏览器原生 select 外观。发送按钮至少 34px 高、左右 padding 12px、8px 圆角，使用 `black` 背景和 `white` 文字。按钮 active 下移 1px，hover 降至 `.88` opacity。提示文字与设计稿一样位于表单下方 8px，使用 12px muted 文本和 1.5 行高。在 340px 抽屉中保持单行排列，输入区优先收缩；极窄屏仅在确实无法容纳时重排，禁止横向滚动。

成员菜单相对成员行定位在 `right: 2px; top: calc(100% - 4px)`，最小宽度 112px、padding 4px、10px 圆角、`line-strong` 边框，并严格使用设计稿明暗主题的浮层阴影。菜单项高 32px、左右 padding 10px、7px 圆角，使用 13px/600 文本；选中角色在行尾显示 Check 图标。分隔线为 1px，margin `4px 2px`；危险项使用 danger 色以及设计稿对应的明暗 hover 背景。所有颜色、背景、边框和文字 transition 均为 150ms。菜单通过 Lucide 图标和文字表达，不使用 emoji。

## 组件与数据边界

`NoteEditorDrawers` 只负责抽屉容器、标题栏、遮罩、关闭行为和响应式边界，并把实时参与者传给协作面板。

`CollaboratorsPanel` 负责加载和组织 ACL、邀请及操作状态。组件内部拆分为可见性行、成员列表、成员行、角色菜单、邀请表单和邀请成功反馈等小单元，避免继续扩大单一 JSX 块。

ACL API 响应从 `{ userId, role }` 扩展为兼容结构：保留 `userId` 和 `role`，并增加可选的 `displayName`、`email`、`avatarUrl`。后端只返回协作侧栏所需的公开展示字段，绝不返回密码或其他账户敏感字段。创建者作为所有者包含在统一成员结果中，保证设计稿中的“我 / 所有者”行稳定存在。

邀请列表保留 `_id`、`inviteeEmail`、`role`、`status`、`createdAt` 和 `expiresAt`。前端仅把 `pending` 邀请合并到成员列表末尾；`accepted` 成员由 ACL 数据展示，避免重复。

## 交互与数据流

打开抽屉后并行读取 ACL 和邀请列表。ACL 失败时展示面板级错误；邀请列表因权限不可见时不把它误报为“没有邀请”，而是仅隐藏邀请管理能力。切换标签页回到前台时刷新数据。

只有所有者可以看到成员管理和邀请操作。`readOnly` 或非所有者视角保留成员与可见性展示，但不显示可执行控件。

角色修改和移除操作在对应成员行进入 busy 状态，成功后重新读取 ACL，失败则保留原数据并通过现有 toast 报错。危险操作位于菜单底部并使用危险色；不做无反馈的乐观删除。

发送邀请前校验非空且符合邮箱格式。发送成功后清空输入、刷新列表，并使用 toast 告知结果；协作面板本体仍保持设计稿的三个分组，不插入设计稿之外的成功卡片。由于后端当前只向已注册邮箱对应账户生成站内通知，提示文案使用“邀请通知”而不是不真实的“邮件通知”。

重新发送采用“先创建新邀请，成功后撤销旧邀请”的顺序。这样新邀请创建失败时旧邀请仍然有效；新邀请成功但旧邀请撤销失败时刷新列表并提示存在重复有效邀请，避免把部分成功伪装为完整成功。撤销邀请成功后刷新列表。

菜单支持点击外部和 Escape 关闭。抽屉支持 Escape 关闭，关闭按钮和所有交互控件具有可见 focus 状态与准确的 `aria-label`。触控目标在可用空间内尽量达到 44px；设计稿中较小的视觉按钮通过透明命中区补足，不改变视觉尺寸。

## 状态与降级

- 初次加载：以与成员行等高的轻量骨架占位，避免布局跳动。
- 空成员：显示克制的空状态文本，不引入额外卡片。
- 操作中：仅禁用相关行或表单，其他内容仍可阅读。
- 网络失败：保留最近一次成功数据并显示 toast；首次加载无缓存时显示内联错误与重试入口。
- 图片失败：回退为姓名或邮箱首字符头像。
- 缺少展示资料：优先显示 `displayName`，其次邮箱，最后使用缩短后的用户标识。
- 实时连接可用但成员不在 awareness：按设计稿显示灰色离线点；实时连接整体不可用时不显示圆点，避免把“未知”误表达为“离线”。

## 验收标准

- 与设计稿并排比较时，340px 抽屉、56px 标题栏、14px 内容边距、16px 分组节奏、成员行、胶囊权限控件、邀请表单和浮层菜单的尺寸与结构一致；逐项检查本节列出的 CSS 数值，不接受仅凭观感近似。
- 浅色与暗色状态、hover/focus/active/disabled、在线/离线、所有者/普通成员/待接受邀请的颜色与形态均与设计稿一致。
- 不再出现旧版嵌套卡片、“刷新状态”按钮、裸 ObjectId、英文角色值或独立邀请列表。
- 所有设计稿中的主要交互均能调用现有 API 完成，并对失败和处理中状态给出明确反馈。
- 所有者、普通成员、待接受邀请、只读视角和窄屏布局均有明确呈现。
- 改造不改变评论抽屉、编辑器内容和实时协作连接逻辑。
