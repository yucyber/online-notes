# 知识库笔记选择衔接设计

## 背景

知识库页的“从笔记选择”目前只跳转到“我的笔记”，没有携带当前知识库，也不会自动进入批量管理。批量管理状态下，选择圆圈使用绝对定位，覆盖了部分笔记标题。

## 目标

- 从已选中的知识库进入笔记页时，自动进入批量选择模式。
- 加入面板默认选中来源知识库，用户勾选笔记后可直接加入。
- 选择圆圈在列表布局中占据独立空间，不覆盖标题。
- 保留用户从“我的笔记”手动进入批量管理的现有流程。

## 交互与数据流

知识库页把入口链接生成为 `/dashboard/notes?select=knowledge-base&knowledgeBaseId=<id>`。笔记页只在 `select=knowledge-base` 且存在 `knowledgeBaseId` 时自动开启选择模式，并将该 ID 传给加入面板。加入面板优先选择该知识库；如果 ID 无效或不可见，则回退到第一个可用知识库。

用户点击“完成”后只退出当前选择状态，不修改 URL 中已有的搜索或分页参数。重复加入仍沿用后端幂等约束和现有成功提示。

## 布局

选择控件从覆盖层移入笔记主行，作为固定宽度的行内按钮。按钮具备明确的 `aria-label` 和选中状态，标题区域自然向右排列。选择模式仍保留整行点击能力，标题链接和行操作在选择模式下不承担导航职责。

## 边界与失败降级

- 没有选中知识库时，知识库页仍可跳转到普通笔记页。
- URL 中的知识库不存在时，加入面板回退到第一个可用知识库。
- 知识库列表加载失败时沿用现有错误提示。
- 不修改后端 API、数据库结构、分页或筛选逻辑。

## 验收标准

- 从知识库入口跳转后，无需再次点击“批量管理”。
- 勾选一篇笔记后，加入控件显示来源知识库为目标。
- 选择圆圈与任何长度的标题都不重叠。
- 普通笔记浏览和手动批量管理行为保持不变。
