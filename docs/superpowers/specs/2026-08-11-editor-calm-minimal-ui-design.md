# 编辑器 Calm Minimal UI 设计

日期：2026-08-11
状态：已确认，待实施计划

## 目标

重构笔记编辑页的视觉层级和核心交互，使界面更简洁、耐看，并把正文编辑放在视觉中心。设计避免大面积强色块、重阴影和含义不清的文字按钮，使用雾蓝、白色和深石墨构成低干扰界面。

本设计只覆盖编辑器页面及其直接依赖的反馈组件，不改变仪表盘、笔记列表和后台业务规则。

确认稿位于 `docs/ui-mockups/editor-calm-minimal-20260810.html`。

## 设计原则

1. 正文优先：导航、属性和协作信息不得长期挤压编辑区域。
2. 状态面向用户：不展示 API 延迟、WebSocket 开关等开发指标，只展示会影响当前操作的结果。
3. 渐进披露：错误、恢复操作和次要信息在需要时出现，不常驻占位。
4. 图标一致：沿用项目已有 `lucide-react`，不手绘图标，不混用多个图标体系。
5. 单一编辑体验：用户不需要理解 Markdown 与富文本之间的模式区别。

## 页面结构

### 左侧导航

- 使用浅色背景和低对比边界，避免形成厚重色块。
- 顶部包含品牌与 `PanelLeftClose` 收起按钮。
- 支持拖拽调整宽度，宽度限制应防止导航过窄或挤占正文。
- 收起时隐藏品牌、搜索、菜单和状态卡片，只保留约 52px 的边缘恢复轨道。
- 恢复轨道使用 `PanelLeftOpen`，点击后恢复上次宽度。
- 收起状态和用户调整后的宽度保存在本地，刷新后保持。

### 顶部信息区

- 展示面包屑、笔记标题和少量持续状态。
- 删除常驻的“重试”和“保存”按钮。
- 正常编辑时只显示低干扰自动保存状态，如“正在保存…”和“已自动保存”。
- 协作降级等持续状态使用用户语言，例如“实时协作暂不可用，已离线编辑”。
- 不向普通用户展示“API 正常”“55ms”“YWS off”等诊断信息。

### 编辑工具栏

- 保留文本格式、段落、撤销和重做等高频操作。
- 图片、链接、表格等内容统一放入工具栏的“插入”分组，不使用右下角悬浮加号。
- 评论和协作者入口使用 `MessageSquare`、`Users` 图标按钮。
- 所有纯图标按钮必须包含 `aria-label`，并在鼠标悬停和键盘聚焦时显示一致的 tooltip。
- Tooltip 向容器内部展开，不得被页面边界或父容器裁切。

### 正文与右侧辅助面板

- 正文采用居中的纸张式编辑区域，使用轻边框和极弱阴影。
- 右侧辅助面板承载目录、协作者和属性。
- 右侧面板顶部提供 `PanelRightClose`，收起后正文占用释放的空间。
- 收起后右侧边缘保留 `PanelRightOpen` 恢复入口。
- 左右面板独立控制，按钮文案分别为“收起左侧导航”和“收起右侧面板”，不使用含糊的“收起侧栏”。
- 小屏幕默认收起右侧面板；更窄的屏幕同时默认收起左侧导航。

### AI 助手入口

- 右下角只保留一个低干扰的 AI 助手入口。
- 不与“插入内容”按钮组成悬浮按钮组。
- AI 面板打开后应避免遮挡自动保存状态和 Toast。

## 编辑模型

编辑器对用户呈现单一富文本体验，不再显示“富文本 / Markdown”模式切换。

- Tiptap 作为统一编辑表面。
- Markdown 快捷输入通过 input rules 转换为对应富文本节点。
- 粘贴 Markdown 时，在能够可靠识别的情况下转换为富文本；普通文本和 HTML 粘贴保持原有语义。
- 已有 Markdown 笔记在加载时转换到统一文档模型，保存时遵循现有后端内容契约。
- 转换失败不得静默丢失内容，应保留原始文本并通过统一 Toast 告知用户。

实施前需要用现有笔记样本验证标题、列表、引用、代码块、链接、图片和表格的往返转换，避免仅删除模式开关而破坏旧内容。

## 自动保存与只读权限

### 自动保存

- 编辑变更触发防抖自动保存，不要求用户点击“保存”。
- 状态至少包含：正在保存、已自动保存、已保存到本地、保存失败。
- 状态文本不抢占焦点，不使用成功 Toast 反复打扰用户。
- 保存失败时保留本地内容，并通过统一 Toast 提供“重新保存”。
- 可继续保留 `Ctrl/Cmd + S`，其语义为立即触发保存，而不是依赖手动保存按钮。

### 只读权限

- 只读用户不能修改标题、正文、属性、标签、评论状态或协作内容。
- 编辑器、工具栏和写操作入口必须在交互层禁用，不能仅依赖保存接口返回错误。
- 只读状态以轻量标签表达；用户尝试受限操作时最多提示一次统一 Toast。
- 服务端 ACL 仍是最终权限边界，前端禁用只负责体验和减少无效请求。

## 统一 Toast

项目继续使用已有 `react-hot-toast`，但由统一封装控制视觉、位置和重复策略，业务组件不得各自实现不同的错误条。

- 固定在页面右上角，与 AI 助手入口错开。
- 同一时间最多展示三条，新消息位于上方。
- 结构统一为：状态图标、标题、简短说明、可选操作和关闭按钮。
- 同类错误在短时间内合并，避免请求重试导致连续刷屏。
- 普通错误约 5 秒后消失；需要用户处理或可能造成数据风险的错误保持显示。
- 操作按钮使用明确动词，例如“重新保存”“重新连接”“重试生成”。
- 保存、协作和 AI 错误使用同一套尺寸、圆角、阴影、排版与动效，仅图标和语义色不同。
- Toast 容器使用 `aria-live`，错误项使用合适的 alert/status 语义；关闭后焦点不得丢失。

持续状态和 Toast 的职责不同：持续状态说明当前模式，如离线编辑；Toast 说明刚发生的事件及可执行操作。两者可以同时存在，但不得重复长篇错误信息。

## 响应式与可访问性

- 桌面端优先保障正文宽度，左右面板可独立收起。
- 小屏幕不出现横向滚动，工具栏允许分组折叠或进入更多菜单。
- 交互目标建议不小于 40×40px；移动端不小于 44×44px。
- 键盘可访问所有收起、展开、评论、协作、AI 和 Toast 操作。
- 焦点样式必须可见，图标按钮不能只依赖 hover 解释用途。
- 动画控制在 150–200ms，并遵循 `prefers-reduced-motion`。
- 正文、按钮和状态文本满足常规对比度要求。

## 组件边界建议

- `NoteEditorShell`：负责编排布局和面板状态，不承载 Toast 视觉实现。
- `NoteEditorHeader`：展示标题、持续状态和自动保存状态。
- `NoteEditorMetadataPanel`：承载右侧目录、协作者和属性，并支持收起。
- 编辑工具栏：统一插入分组、评论和协作者图标入口。
- Toast 适配层：统一封装 `react-hot-toast` 的错误类型、去重、持续时间和操作按钮。
- Tiptap 编辑桥接层：处理 Markdown 输入、粘贴和旧内容转换。

具体文件拆分由实施计划结合现有组件职责确定，不为视觉调整引入新的全局状态库。

## 验收标准

1. 左侧导航和右侧辅助面板都可收起、恢复，正文随可用空间正确扩展，按钮不遮挡内容。
2. 刷新页面后保留用户的面板状态和左栏宽度。
3. 标题栏不再常驻“重试”和“保存”，自动保存状态准确反映保存过程。
4. 保存、协作和 AI 错误全部使用右上角统一 Toast；同类错误不会重复刷屏。
5. 评论、协作者、面板控制和 AI 使用 Lucide 图标，并具备 tooltip 与可访问名称。
6. 插入内容位于工具栏分组，右下角只有 AI 助手入口。
7. 用户无需切换 Markdown/富文本模式；常用 Markdown 输入可转为富文本，旧内容无丢失。
8. 只读用户无法在前端产生任何有效写入，服务端仍拒绝越权请求。
9. 常见桌面宽度、开发者工具挤压后的窄视口和移动断点均无横向溢出或控件重叠。
10. 编辑器相关单元测试、组件测试和关键浏览器验收通过。

## 非目标

- 不重做整个 Dashboard 信息架构。
- 不替换 Tailwind、Radix、Lucide 或 Tiptap。
- 不新增第二套 Toast 库或完整 UI 组件库。
- 不在本轮重新设计 AI 对话内容、后端协作协议或 ACL 模型。
- 不展示面向开发人员的网络延迟和底层连接诊断；这些信息继续进入日志或调试工具。
