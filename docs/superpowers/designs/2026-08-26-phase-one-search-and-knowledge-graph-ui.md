# 第一阶段搜索证据与知识图谱 UI 审核稿

> 状态：待产品审核。本文只确定界面和交互，不授权修改前端生产代码。

## 1. 视觉方向

沿用当前项目的“克制、内容优先的知识工作台”风格：浅灰白面板、细边框、低饱和蓝灰强调色、紧凑但不拥挤的排版。继续使用项目现有字体、`PrototypeGlyph`、按钮和 `--product-*` / `--surface-*` token，不采用设计库建议的粉色强调色、衬线字体或夸张大标题，避免与现有工作台割裂。

设计记忆点不是装饰，而是“证据可见”：搜索结果直接说明命中了笔记的哪一节；知识图谱节点选中后直接说明它来自哪些笔记。

## 2. 搜索结果：在原笔记行内展示命中 Chunk

### 2.1 桌面布局

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ React Diff                                             更新于 8/26 · 前端 │
│ React / 性能优化                                               语义相关    │
│ useMemo 不能解决所有 diff 开销，列表 key 不稳定时仍会导致整棵子树……       │
│                                                    另外命中 2 处 ›         │
└────────────────────────────────────────────────────────────────────────────┘
```

- 保留现有 `NotesListCard` 的标题、更新时间、分类、标签和操作按钮。
- 仅在语义搜索开启且后端返回 `bestChunk` 时，在元信息下增加一条“命中证据带”。
- 标题路径使用 `React / 性能优化`，缺少路径时显示“正文命中”。
- `semantic` 命中显示“语义相关”；关键词命中才高亮实际查询词，不能给纯语义结果制造伪高亮。
- Chunk 文本桌面最多两行；整条证据带可点击并进入原笔记，第一版先打开笔记，不承诺精确滚动定位。
- “另外命中 N 处”使用弱链接样式。第一版点击后在当前行向下展开最多 3 条额外片段，不弹 modal。

### 2.2 移动端

```text
┌──────────────────────────────┐
│ React Diff                   │
│ 8/26 · 前端 · 2 个标签       │
│ React / 性能优化   语义相关  │
│ useMemo 不能解决所有……      │
│ 另外命中 2 处 ›              │
└──────────────────────────────┘
```

- 证据路径和徽标允许换行，不使用横向滚动。
- 操作按钮维持至少 44×44px 点击区域。
- 普通笔记列表、空查询和关键词搜索无 Chunk 证据时完全保持现有密度。

### 2.3 状态与反馈

| 状态 | 展示 |
| --- | --- |
| 正在检索 | 保留列表高度的 skeleton，避免结果跳动 |
| Vector 失败、hybrid 降级 | 列表顶部弱提示“语义检索暂不可用，已显示关键词结果” |
| 0 结果 | “没有找到相关笔记”并建议缩短问题、切换模式或清除筛选 |
| Chunk 缺失 | 使用旧 `preview`，不显示空证据框 |

## 3. 知识库页面：从上下堆叠改为主从工作区

当前页面把笔记长列表放在图谱上方，图谱容易落到首屏之外。第一版改为“知识库导航 + 独立内容视图”，图谱成为真正的主功能，而不是笔记列表末尾的附加卡片。

### 3.1 桌面端结构

```text
┌──────────────┬─────────────────────────────────────────────────────────────┐
│ 知识库  4    │ Codex 配置指南                              从笔记选择      │
│              │ 12 篇笔记 · 更新于今天                                     │
│ ● Codex 指南 │                                                             │
│   React 学习 │ [ 知识图谱  12节点/10关系 ] [ 笔记 12 ]                    │
│   前端工程化 │─────────────────────────────────────────────────────────────│
│   随手记录   │ 图谱来源存在 1 条模型兼容提示                     查看 ›    │
│              │ ┌──────────────────────────────────────┬──────────────────┐ │
│              │ │                                      │ 节点详情         │ │
│              │ │          React Flow 画布             │ React Diff       │ │
│              │ │    节点 · 连线 · 中文关系标签        │ 概念 · 92%       │ │
│              │ │                                      │ 来源笔记 2 篇    │ │
│              │ │ 图例                        控制器    │ · Codex 指南     │ │
│              │ └──────────────────────────────────────┴──────────────────┘ │
└──────────────┴─────────────────────────────────────────────────────────────┘
```

### 3.2 信息层级

1. 页面级标题“知识库”和“新建知识库”保持现状。
2. 左栏宽度约 264px，仅负责切换知识库；条目展示名称、描述单行和笔记数。
3. 右侧详情头展示知识库名称、描述、笔记数和“从笔记选择”。
4. 详情使用两个页签：
   - `知识图谱`：默认打开，徽标显示节点/关系数。
   - `笔记`：显示现有笔记列表和移除操作。
5. “生成提案 / 保存图谱”放在知识图谱页签工具栏右侧，不和“从笔记选择”混在一起。

这样既保留笔记管理，也避免笔记列表把图谱推到首屏之外。

## 4. React Flow 图谱

### 4.1 画布

- 使用 `@xyflow/react`，初始用 dagre 从左到右布局。
- 桌面画布最小高度 520px；1024px 下 460px；移动端 420px。
- 背景使用极淡点阵，只作为空间参照。
- 内置缩放、平移、节点拖拽、Fit View；另提供“重新布局”按钮。
- 节点数大于 20 时提供可折叠 MiniMap；20 个以内不显示。
- 节点数大于 60 时关闭边动画和不必要阴影，保证交互流畅。

### 4.2 节点

```text
┌─▌─────────────────┐
│ ▌ React Diff      │
│ ▌ 概念 · 92% · 2篇│
└───────────────────┘
```

- 圆角矩形，不使用气泡标签。
- 节点主体保持面板色，只用左侧 3px 色条区分概念、实体、主题、论断；同时显示中文类型，不能只靠颜色表达。
- label 最多两行，完整文本放入 tooltip。
- 选中节点使用项目强调色边框和轻量 ring，不使用强发光。

### 4.3 关系边

- 默认 1.5px 中性细线，选中节点后仅高亮其一跳关系。
- 在线段中点展示“包含 / 使用 / 依赖 / 相关”等中文标签。
- 缩放低于 0.6 时隐藏关系文字，放大后恢复。
- 未识别的英文 relation 原样显示，不显示空白或报错。

### 4.4 详情面板

- 未选中节点时不占宽度，画布全宽。
- 点击节点后从画布右侧展开 288px 面板，展示 label、类型、置信度和来源笔记。
- 来源笔记使用现有 `noteIds` 与知识库链接数据映射，点击打开笔记。
- 第一阶段不展示“关系原文证据”，因为 `evidenceChunkIds` 属于第二阶段；界面不伪造尚不存在的数据。
- 移动端详情改为画布下方 bottom sheet，不覆盖缩放控制器。

## 5. warnings 字段的 UI

`warnings` 不属于图谱节点或关系，而是生成提案时需要用户注意的非致命提示，例如模型名或配置可能随版本变化。处理方式：

- `warnings.length === 0`：完全不占空间。
- 非空：在画布上方展示一行浅琥珀提示，默认只显示第一条和数量。
- 点击“查看”展开全部；不使用错误红色，因为图谱仍然可保存和使用。
- 已保存图谱重新加载时仍展示对应 warnings，避免提示随保存消失。

## 6. 响应式规则

| 宽度 | 布局 |
| --- | --- |
| ≥1280px | 264px 知识库栏 + 详情；节点详情在画布右侧 |
| 768–1279px | 220px 知识库栏 + 详情；节点详情覆盖式窄面板 |
| <768px | 知识库栏改为顶部选择器；页签横排；详情在画布下方 |
| 390px | 所有操作可换行，画布不超过视口宽度，无页面横向滚动 |

必须在 390、768、1024、1440px 下检查空图谱、长节点名、warnings、暗色模式和 60 节点数据。

## 7. 可访问性与动效

- 所有图谱控制按钮有中文 `aria-label` 和可见 tooltip。
- Tab、节点、来源笔记和折叠按钮支持键盘访问，focus ring 不移除。
- 正文和关键标签对比度至少 4.5:1；颜色不是节点类型的唯一表达。
- 动效仅用于详情面板进入和选中态，150–220ms；遵守 `prefers-reduced-motion`。
- 加载和错误使用 `aria-live` / `role="alert"`，避免只有视觉颜色变化。

## 8. 审核后实施边界

审核通过后才执行以下前端改动：

1. 扩展语义搜索响应类型和页面状态，增加 `SearchHitEvidence`。
2. 安装 `@xyflow/react`、`dagre`、`@types/dagre`。
3. 新建图谱转换、自动布局和画布组件。
4. 将知识库详情改为“知识图谱 / 笔记”页签布局。
5. 补齐组件测试、暗色模式和四档响应式浏览器验证。

不在第一阶段加入 AI 问答、图谱一跳检索、`evidenceChunkIds` 或自动整理写操作。
