# 在线笔记平台技术架构方案

更新日期：2026-06-04

## 1. 当前技术栈

- 前端：Next.js / React / TypeScript，App Router，前端 BFF route handlers。
- 后端：NestJS / TypeScript，Mongoose，Redis，Passport JWT。
- 协作：Yjs + y-websocket，WebSocket 层使用 JWT 适配器。
- 数据：MongoDB，笔记、标签、分类、权限、资源、语义向量等数据由后端统一管理。
- AI：后端统一 AI Gateway，前端不再直连模型供应商。

## 2. 核心架构

```text
Browser
  -> Next.js UI
  -> Next.js BFF /api/*
  -> NestJS /api/*
  -> MongoDB / Redis / AI Gateway / y-websocket
```

前端负责交互、编辑器、画板、思维导图、AI 调用入口和流式展示。后端负责鉴权、权限边界、业务数据、协作 token、缓存、语义检索、AI provider 路由和模型密钥管理。

## 3. AI 架构现状

当前 AI 能力统一走后端 `notes-backend/src/modules/ai`：

- 文本生成默认路由：SenseNova `deepseek-v4-flash`
- 推理/长上下文默认路由：MiMo `mimo-v2.5-pro`
- 向量模型：SiliconFlow `Qwen/Qwen3-Embedding-8B`
- reranker：SiliconFlow `Qwen/Qwen3-Reranker-8B`

已迁移能力：

- AI 写作：`POST /api/ai/writer` 和 `POST /api/ai/writer/stream`
- 思维导图：`POST /api/ai/mindmap`
- Mermaid 图表：`POST /api/ai/mermaid`
- AI Pet 文本对话：`POST /api/ai/pet`
- 多笔记聚合摘要：`POST /api/ai/summary`
- 单篇笔记摘要：`AiService.generateSummary`
- embedding：`EmbeddingService -> AiService.generateEmbedding`
- 主题命名：`SemanticService -> AiService.generateTopicName`

Coze、Zhipu、ModelArk 不再作为当前主链路或 fallback。相关探索记录已归档到 `docs/history/`。

## 4. 配置边界

模型密钥只放后端环境变量。前端只保留公开配置，例如 `NEXT_PUBLIC_API_URL`，不得再放 `NEXT_PUBLIC_COZE_API_KEY` 这类模型密钥。

后端 `.env` 需要包含：

- `MIMO_API_KEY`
- `MIMO_BASE_URL`
- `MIMO_MODEL`
- `SENSENOVA_API_KEY`
- `SENSENOVA_BASE_URL`
- `SENSENOVA_TEXT_MODEL`
- `SILICONFLOW_API_KEY`
- `SILICONFLOW_BASE_URL`
- `SILICONFLOW_EMBEDDING_MODEL`
- `SILICONFLOW_RERANKER_MODEL`
- `AI_TEXT_PROVIDER`
- `AI_REASONING_PROVIDER`
- `AI_EMBEDDING_PROVIDER`
- `AI_RERANKER_PROVIDER`

提交前至少运行：

```powershell
cd notes-backend
$files = Get-ChildItem -Path test -Filter *.test.ts | Sort-Object FullName | ForEach-Object { $_.FullName }
node --require ts-node/register --require tsconfig-paths/register --test $files
npm run build
```

```powershell
cd notes-frontend
npm run type-check
npx jest __tests__/editor.markdown.spec.tsx __tests__/editor.tiptap.auth.spec.tsx __tests__/editor.tiptap.spec.tsx --runInBand --no-cache --coverage=false
```

npm run check:api-contract
npm run check:ai-config
