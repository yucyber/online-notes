# 前后端架构详细设计

更新日期：2026-06-04

## 1. 前端边界

前端位于 `notes-frontend`，使用 Next.js App Router。主要职责：

- 页面和交互：`src/app`、`src/components`
- API 客户端：`src/lib/api.ts`
- AI 写作流：`src/lib/ai-writer.ts`
- AI Gateway 前端包装：`src/lib/ai-gateway.ts`
- AI BFF route handlers：`src/app/api/ai/*`

前端 AI BFF 不持有模型密钥，只负责：

- 读取用户 cookie 中的 `notes_token`
- 转发 Authorization 到 NestJS
- 保持现有前端调用形态
- 对流式响应做透传

## 2. 后端边界

后端位于 `notes-backend`，使用 NestJS。主要模块：

- `auth`：注册、登录、JWT 当前用户
- `notes`：笔记 CRUD、ACL、锁、推荐、摘要触发
- `categories` / `tags`：分类和标签管理
- `boards` / `mindmaps`：画板与思维导图资源
- `semantic`：语义搜索、主题发现、主题转标签
- `ai`：统一 AI Gateway、AI 业务接口
- `ws`：协作 WebSocket JWT 适配

后端统一设置 `/api` 前缀，统一响应包为：

```json
{
  "code": 0,
  "message": "OK",
  "data": {},
  "requestId": "...",
  "timestamp": "..."
}
```

使用 `@Res()` 直接写入的流式接口不走普通 JSON envelope。

## 3. AI 调用链路

```text
React component
  -> Next.js /api/ai/*
  -> NestJS /api/ai/*
  -> AiService
  -> AiGatewayClient
  -> MiMo / SenseNova / SiliconFlow
```

当前后端 AI 端点：

| Endpoint | 用途 | 响应 |
| --- | --- | --- |
| `POST /api/ai/writer` | 非流式 AI 写作 | JSON envelope |
| `POST /api/ai/writer/stream` | 流式 AI 写作 | `text/event-stream` |
| `POST /api/ai/mindmap` | 生成/扩展/优化思维导图 | JSON envelope |
| `POST /api/ai/mermaid` | 生成 Mermaid 图表代码 | JSON envelope |
| `POST /api/ai/pet` | AI Pet 文本聊天 | `text/event-stream` |
| `POST /api/ai/summary` | 多笔记聚合摘要 | JSON envelope |

AI Pet 当前只支持文本。图片聊天需要后续接入 MiMo omni 或其他视觉模型后再恢复。

## 4. 语义检索与知识整理

语义链路当前由 `semantic` 模块承载：

```text
Note content
  -> EmbeddingService
  -> AiService.generateEmbedding
  -> SiliconFlow Qwen embedding
  -> MongoDB vector field / vector search
```

主题发现流程：

```text
notes
  -> embeddings
  -> kmeans clustering
  -> AiService.generateTopicName
  -> topic proposal
  -> convert to tags after user action
```

后续知识库、知识图谱、RAG、LangGraph workflow 应以 `knowledgeBaseId` 为默认边界，不应把全量笔记混成一个图或一个向量空间。

## 5. 权限和安全

- HTTP API 默认使用 JWT。
- 协作 WebSocket 使用 `JwtWsAdapter`。
- 笔记、画板、思维导图的读写必须复用后端权限边界。
- AI tools 或未来 agent 不能绕过 `NoteAccessService` 直接改用户数据。
- 模型 provider 错误不应泄露 API key，仅暴露缺失配置项名称或供应商错误摘要。
