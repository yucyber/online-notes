# Debug 记录文档格式

Debug 记录统一写入 `docs/debug-records.md`，供本项目所有 agent 检索。

## 追加位置

在 `docs/debug-records.md` 末尾追加新条目。文件顶部保留标题和说明，后续条目按时间倒序或顺序追加均可（保持一种即可）。

## 每条记录的字段

```markdown
## <标题：一句话描述 bug>

- **日期**：YYYY-MM-DD
- **现象**：用户看到什么、怎么触发的。
- **根因**：真正的技术原因，写到能直接指导修复的程度。
- **相关文件**：涉及的代码文件路径。
- **修复方案**：关键改动（可附代码片段）。
- **经验教训**：避免再犯的通用结论。
```

## 写作要求

- 简洁、可检索：标题和现象里包含关键词，方便后续用 `search_content` 命中。
- 根因要"能落地"，不要写"可能是 XX"，要写"确认是 XX"。
- 代码片段用最小可复现的关键行，不贴整段无关代码。
- 经验教训提炼成通用规则，例如"ObjectId 的 `$in` 查询不要依赖 mongoose 隐式 cast"。
